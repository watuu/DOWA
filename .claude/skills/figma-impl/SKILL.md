# Figma 実装と px 照合

このプロジェクト（Pug + Sass + Rollup）で Figma を実装するときの手順。
**「実装 → 目視 → 微調整」で済ませないこと。** 過去に精度が出なかったケースは、ほぼ全部この手順の
2 と 5 を飛ばしたことが原因だった。

## 0. この案件は `doc/design-tokens.md` が正

本件（NIPPON PGM）の Figma はデザインの揺れが大きい。**同じ役割の要素でも画面ごとに値が違う**ため、
Figma の生の値をそのまま拾うと実装がバラつく。トークン系は `doc/design-tokens.md` を正とする。

| 種別 | 正 |
|---|---|
| フォント / 色 / font-size / line-height / letter-spacing / 角丸 | **`doc/design-tokens.md`** |
| 座標・寸法・余白（x / y / w / h、要素間の間隔） | Figma の実測（ドキュメントに記載がないため） |

- Figma の値がドキュメントと食い違ったら **ドキュメントを採用し、Figma には合わせない**
- そのうえで**食い違い自体は `doc/design-tokens.md` の「6. 未決事項」に追記する**。黙って寄せない
- ドキュメントに無いトークンが出てきたら、勝手に一発ものの値を入れず、まずドキュメントに追記してから使う
- 座標・寸法は Figma 実測が正だが、**同じ画面の他要素と矛盾する値は採用前に確認する**（6節を参照）
- px 照合の spec に書く `fontSize` / `lineHeight` / `letterSpacing` / `borderRadius` / 色も、
  **Figma の値ではなくドキュメントの値を書く**。ここを Figma 由来にすると揺れをそのまま検出してしまう

## 1. 先に採寸する（実装より前）

`get_metadata` でセクション配下のノードを一括取得し、必要な数値を控える。

- 各要素の x / y / w / h
- `get_design_context` で font-family / font-size / line-height / letter-spacing / 色
- **コンポーネント（Figma のインスタンス）は「箱の高さ」も控える。** これが最重要。

控えた **node-id は必ず SCSS のコメントに書く**。あとで再検証できないコメントは書かない。

```scss
/*----------------------------------------------------
    p-option（オプション）
    Figma: SP 1725-3735 / PC 1549-4594
----------------------------------------------------*/
```

## 2. 「コンポーネントの箱」を先に合わせ、余白はあとで入れる

**やってはいけない組み方**：隣接要素の Figma 座標の引き算だけで `margin-top` を決める。

```scss
// ✗ これをやると、土台が間違っていても数字が合ってしまう
// Figma実測：ラベル上端(1139) → 見出し上端(1257) = 118px。
// 実装のラベルは丸アイコンが32pxあるため 118 - 32 = 86px
margin-top: 86/16+rem;
```

これは「コンポーネントの高さが Figma と違う」というバグを、余白のマジックナンバーで
打ち消しているだけ。**誤差は消えず別の場所に押し出される**し、そのコンポーネントを使う
他のページ全部が同じだけずれる。

**正しい順序**

1. コンポーネント自身の w / h を Figma と一致させる
2. そのうえで余白は Figma の実測差をそのまま入れる（上の例なら 118 − 18 = 100px）

## 3. インライン SVG は必ず width と height の両方を殺す

`svg(width=32 height=32)` のように属性を持った SVG は、CSS で `width` だけ指定しても
**height 属性の値（32px）がそのまま残る**。アイコンを含む行がまるごと 32px 高くなる。

```scss
// ✗ 高さが素通りする
i { width: 12/16+rem; }

// ○
i {
    display: block;
    width: 12/16+rem;
    svg { display: block; width: 100%; height: auto; }
}
// もしくは箱に width / height を両方指定する
.c-btn-more__arrow { width: 35/16+rem; height: 35/16+rem; }
```

実装後、`figma-verify` とは別に**下の「アイコン一括監査」スニペットをブラウザの DevTools
コンソールに貼って走らせる**。スニペットは開いているページ1枚しか見ないので、
触ったページを1枚ずつ開いて実行すること。

## 4. 位置は「率」で、寸法は px で

コンテナ幅に対する比率で決まっているものは、割り算の元の数を残したまま比率で書く。

```scss
left: 73.125%;  // 1053 / 1440
top: 45.5%;     // 136.5 / 300
```

サイズ・余白・字送りは px 起点で書く。

- 既存コードは `#{16/16+rem}` 形式で統一されている。既存ファイルに手を入れるときはそれに合わせる
- 単に px 単位を付けたいだけなら `src/sass/Base/_config.scss` の `px()` 関数が使える
- ブレークポイントの mixin（`sp` / `tab` / `pc` / `wide` 等）と実際の境界値も `_config.scss` の
  `$breakpoints` が定義元。**PC 1600 / SP 402 を検証ビューポートに使う**
  （SPの 402 は FigmaのSPアートボード幅。`Base/_font.scss` の rem 基準も `16/402*100vw` に揃えてある）

## 5. 実装後に必ず px 照合する

### 手順

```bash
# 0) 初回のみ（Chromiumの取得だけ。@playwright/test は導入済み）
npx playwright install chromium

# 1) ★ビルドし直す。忘れると古い dest/ を測るので、結果は「合っている」も「ズレている」も無意味
npm run sass && npm run pug

# 2) dest/ を配信する（ローカル Apache 等がある環境ならそちらでもよい）
cd dest && python3 -m http.server 8899

# 3) 仕様書を作って、2 の URL を url に書く
cp tools/figma-spec.example.json tools/spec/<page>.json

# 4) 照合
npm run verify -- tools/spec/<page>.json

# 5) ★性質の違う4方式をまとめて回す（spec照合 / node-id照合 / カンプ照合 / DOM健全性）
npm run verify:all

# 書き漏れだけ見たいとき
npm run verify:coverage
```

### 照合は「外側から3段」で閉じる

**部品単体の寸法だけを並べた spec は、余白の抜けを1件も検出しない。**
実際に「部品はすべて 0 件差分・ページは最大 566px ずれ」という状態が起きた。
原因は、部品の間の余白がどの spec 項目にも現れていなかったこと。次の順で外から閉じる。

| 段 | 何を書くか | これが無いと見逃すもの |
|---|---|---|
| 1. ページ | パンくず・フッターの**絶対 y**、ページ全体の高さ | ブロック間の余白の抜け（積み上がって数百pxになる） |
| 2. ブロック | パネル・セクション・一覧の **`h`** | 内側の余白の間違い、行の高さの累積ズレ |
| 3. 部品 | `w` `h` ＋ タイポ ＋ 装飾 | 箱の大きさ、色、罫線 |

### 1つの方法では必ず穴が残る。性質の違う4つを重ねる

`npm run verify:all` でまとめて回す（`dest/` を配信してから）。
**どれか1つで十分ということは無い。**見ている対象がそれぞれ違う。

| 方法 | 期待値の出どころ | 拾えるもの | 拾えないもの |
|---|---|---|---|
| ① `npm run verify`（figma-verify）| **手書きの spec** | 色・字送り・罫線まで精密 | **書き忘れた項目は素通り** |
| ② `npm run verify:nodes`（figma-nodes）| **SCSSの `Figma:` コメント**＋ノード寸法 | 手書き不要。箱の高さのズレ | 色・字送りは見ない |
| ③ `npm run verify:compare`（figma-compare）| **デザインの書き出し画像** | 手書き不要。要素・余白の抜け | ダミーテキスト差で誤検出 |
| ④ `npm run verify:sanity`（figma-sanity）| **何も要らない** | 効かないgap・潰れ・はみ出し | 値の正しさは見ない |

**②が本命。** SCSS に規約で書いている node-id（`Figma: SP 3139-5472 / PC 2548-5368`）を入力にして、
`tools/figma/nodes.json`（Figmaの全ノードの x/y/w/h）から寸法を引き、実測と突き合わせる。
**期待値を1つも書かないので、書き忘れようがない。** node-id を書いていないブロックは一覧に出る。

**③はカンプが手元にあるときだけ使える**が、いちばん強い。デザインの書き出し画像（Figmaのアートボード幅
そのままの JPG）と実装のスクリーンショットを行ごとに比べ、「内容の帯」がどこから何pxずれ始めたかを出す。
実際に「フッターがFigma内で2種類ある」（実装770 / カンプ920）をこれが独立に検出した。

**④は値を知らなくても効く。** 実際に出た2件はどちらもこれで拾える。
- ドロワーの `gap: 30` が `<nav>` に付いていて子が `<ul>` 1つ → 項目間に効いていなかった
- 言語切替の 1px 罫線が `flex-shrink` で 0 に潰れて消えていた

わざとそうしている箇所は `tools/spec/.sanity-ignore` に「種別 セレクタ」で書く。

### spec の書き漏れは `npm run verify:coverage` で洗う

`tools/figma-coverage.mjs` が、ビルド済み HTML に出てくる `c-` / `cm-` / `l-` / `p-` のクラスと
`tools/spec/*.json` のセレクタを突き合わせて、次を報告する（抜けがあれば終了コード 1）。

1. **spec のどこからも参照されていないクラス**
2. **spec にはあるが `w` も `h` も書いていないクラス** … 色やフォントだけ見ていて箱が素通りしている状態
3. 片方のビューポートにしか無いセレクタ

意図的に測らない入れ物やモディファイアは `tools/spec/.coverage-ignore` に書く。
**「測らない」と書くこと自体が判断の記録になる**ので、無視リストに入れずに放置しない。

実例：`c-form-required`（必須バッジ）は spec に `fontSize` と `color` しか書いておらず、
箱が Figma の 22px に対して 40.6px あったのを検出できていなかった。2 の報告で拾える。

使えるオプション（**spec のパスを先に書き**、`npm run verify -- <spec> --only SP` のように後ろに付ける）

| オプション | 用途 |
|---|---|
| `--only SP` | 片方のビューポートだけ回す。SP だけ直したときに速い |
| `--tolerance 2` | **x / y / w / h の**許容差（既定 4px）を締める・緩める |
| `--json` | 機械可読出力。差分を数える／別スクリプトに食わせる |

終了コード: `0` 差分なし / `1` 差分あり / `2` **結果が無効**（baseline 未検出）。`--json` でも同じ。

### 許容差はキーごとに違う

`--tolerance` が効くのは位置・寸法（`x` `y` `w` `h`）だけ。**タイポに 4px の許容を使うと
`letterSpacing` の 0 と 0.64px（0.04em × 16px）の違いが素通りする**ので、下は別枠で固定している。

| キー | 既定の許容差 |
|---|---|
| `x` `y` `w` `h` | `--tolerance`（既定 4px）|
| `fontSize` `borderRadius` | 0.5px |
| `lineHeight` | 1px |
| `letterSpacing` | 0.05px |

緩めたいときは spec に `"tolerances": { "letterSpacing": 0.2 }` と書いて上書きする。

### 仕様書に必ず入れる項目

座標だけを見ても精度は出ない。**spec に書いていない属性は永遠に検出されない**ので、
ブロックごとに最低限これを書く。

| 種別 | 項目 |
|---|---|
| 位置・寸法 | `x` `y` `w` `h` |
| **ブロックの高さ** | **囲みブロック・セクション・一覧の `h`** |
| **後続の絶対位置** | **パンくず・フッターなど、下にあるものの `y`** |
| タイポ | `fontSize` `lineHeight` `letterSpacing`（必要なら `fontWeight` `fontFamily`）|
| 装飾 | `borderTop` / `borderBottom`（太さ・色）`borderRadius` `color` `background` |

`w` を書かないと幅ズレが、`h` を書かないとコンポーネントの箱の高さのズレが、
`borderTop` を書かないと罫線の色・太さの間違いが、それぞれ素通りする。

### Figmaの「箱の高さ」と文字の行間は一致しないことがある

コンポーネント化された見出しは、箱が `font-size × 1.2` で、文字だけ 1.4 相当ではみ出す作りになっていることがある
（`inset-[0_..._-16.67%_0]` のような負の inset が出ていたら疑う）。`[text-box-trim:trim-both]` が付いたテキストも
行間より箱が小さい。**後続要素の位置を合わせるには箱に合わせる**。1要素あたり数pxでも、繰り返すと数十pxになる。

実際に出た例：

| 箇所 | 生成コードの行間 | Figmaの箱 | 影響 |
|---|---|---|---|
| h3コンポーネント | 1.4（42px）| 36px | 1セクション6px × 7 = 42px |
| お知らせの日付 | 1.4（22.4px）| 20px | 1行3px × 10行 = 30px |
| 必須バッジ | 1.9（40.6px）| 22px | SPは行が縦積みなので1行18px |

**`get_design_context` の `leading-*` を信じる前に、`get_metadata` でその要素の `height` を見ること。**
両者が食い違ったら箱（`height`）が正。

### アイコンは自前で描かない

`::before` ＋ `clip-path` で形を作ると、Figmaのアセットと違う形になる。実際に
`M6 18L12 12L12 24L0 24L6 18Z`（12×24の箱の下半分に字形）を、箱いっぱいに引き伸ばした別の形で実装していた。
**同じ字形がスプライトにあるなら使い回す**（このプロジェクトは `_symbol.pug` の `#ico_marker` 等）。
箱と字形の大きさが違う場合は、`.c-marker` のように `--marker-size` / `--marker-box` を分けて持たせる。

### 仕様書を書くときの注意

- **色は `#707070` のまま書いてよい**（内部で `rgb(112, 112, 112)` に直してから比較する）。
  ただし**アルファ付きは `rgba(112, 112, 112, 0.5)` か `#70707080` の形で書く**。
  `borderTop` は `"1px solid rgba(112, 112, 112, 0.5)"` のように太さ・線種・色の3つをそろえる
- `letterSpacing` は `"0.04em"` と書ける（`fontSize` を掛けて px に直して比較する）
- 同じセレクタが複数ヒットすると出力行末に `×N` が付く。狙った1つを測るなら `index` を足す。
  `jsClone()` が要素を複製するページがあるので、`×N` が出たら必ず `index` を確認する
- **閉じたアコーディオンなど非表示の要素は h=0 で測れる**（`gsap.set(content, {display, height:0})` のため）。
  表示状態そのものを見たいときは `display` を spec に書く

### 判定は「絶対 y」ではなく「基準からの相対」で

Figma のダミーテキストと実コピーは行数が違うので、ページ下部の絶対 y は必ずずれる。
`baseline` にそのセクションの先頭要素を置き、そのズレを差し引いて比較する。
差し引いたうえで **セクション内の全項目が同じ量ずれている**なら、それはコピー長の差であって
実装ミスではない。ばらついているなら実装ミス。

### 結果を信用してはいけないケース

- **`baseline が見つかりません` が出た回** … 補正 0 のまま比較が走っている。全項目が同じ量
  ずれた表が出るだけなので、差分は読まずにセレクタを直して測り直す（終了コード 2）
- **スクロール連動のリビールが多いページで数値が暴れるとき** … `gsap` のリビールが終わる前に
  測っている。spec の `settle.timeout` / `settle.scrollWait` を伸ばして測り直す
  （`span` を大量に stagger する見出しがあると既定の 1200ms では足りない）
- **JS エラー行が出ているとき** … 出力に `※JSエラー:` が付いた回は、そもそもレイアウトが
  最後まで組まれていない可能性がある。先にそっちを潰す

## 6. Figma 側を読むときの注意

- **色・タイポは 0 節のとおり `doc/design-tokens.md` を先に見る。** Figma を読むのは、
  ドキュメントに載っていない項目（座標・寸法・余白・装飾の有無）を採るときだけ。
- **罫線・塗りの色は `get_design_context` の要約を鵜呑みにしない。** `#707070` と返ってきても
  実体の SVG に `opacity="0.5"` や `stroke-width="3"` `stroke-linecap="round"` が付いていることがある。
  返り値のアセット URL を `curl` で取って中身を見る。
- **SP アートボードは PC のコンポーネントを流用したまま縮小し忘れていることがある。**
  同じ画面の他の SP 要素と矛盾していたら、そのまま採用せず確認する。
- **SP アートボードに無い装飾（罫線など）は、勝手に PC から持ち込まない。**
  無いなら無いのが仕様。持ち込むなら必ず確認を取る。
- 共通コンポーネントを直すときは、**同じクラスを使っている他ページの構成を先に洗う。**
  同じクラスでも子要素の構成が違うことがある（例：`__title` を持つ用法と持たない用法）。
  片方に合わせた `gap` の変更が、もう片方を壊す。

## 7. 報告

- 差分表をそのまま出す。「合わせました」だけで済ませない。
- Figma 側の数値がおかしいと判断して実装を変えた箇所は、必ず理由を添えて挙げる。
- 直さずに残した差分は、隠さず件数と理由を書く。

## アイコン一括監査（コピペ用）

属性の縦横比と実際の描画がずれている SVG を拾う。**対象ページを開いた DevTools の
コンソールに貼る**（ページ1枚につき1回）。

```js
[...document.querySelectorAll('svg')].filter(s => {
    const r = s.getBoundingClientRect();
    const aw = parseFloat(s.getAttribute('width')), ah = parseFloat(s.getAttribute('height'));
    if (!aw || !ah || (!r.width && !r.height)) return false;
    return Math.abs(r.height - r.width * ah / aw) > 1.5;
}).map(s => (s.closest('[class]')?.getAttribute('class') || '?') + ' | ' + s.getAttribute('width') + 'x' + s.getAttribute('height'));
```
